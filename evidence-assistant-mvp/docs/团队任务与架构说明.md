## 一、整体流程图（业务主链路）

```mermaid
flowchart TD
  startNode([开始]) --> chooseTrack{选择赛道}
  chooseTrack -->|赛道一临床| clinicalAsk[用户提问-临床]
  chooseTrack -->|赛道二营养| nutritionAsk[用户提问-营养]
  chooseTrack -->|赛道三评测| evalStart[加载统一测试集]

  clinicalAsk --> rewrite1[临床查询改写]
  nutritionAsk --> rewrite2[营养查询改写]
  rewrite1 --> retrieve[混合检索-向量加关键词]
  rewrite2 --> retrieve

  retrieve --> liveOpt{是否启用在线补检索}
  liveOpt -->|是| liveSearch[PubMed或临床试验补检索]
  liveOpt -->|否| relevance
  liveSearch --> relevance{相关性/越界检查}

  relevance -->|证据不足或越界| refuse[拒答并附伦理声明]
  relevance -->|通过| generate[按赛道人格生成带引用回答]
  generate --> citeCheck[引用校验]
  citeCheck --> fixCite{校验是否通过}
  fixCite -->|否| annotate[追加无法核实提示]
  fixCite -->|是| showUI[展示回答加证据面板]
  annotate --> showUI
  refuse --> showUI

  evalStart --> dualRun[同一题跑Baseline与RAG两路]
  dualRun --> metrics[统计假引用/覆盖率/拒答率]
  metrics --> report[写出评测结果表与典型Case]
  showUI --> endNode([结束])
  report --> endNode
```

## 六、关键返回结构速查

### `AskResponse` 字段

- `answer: str` 最终回答（含声明）
- `citations: list[Citation]` 生成所用引用
- `contexts: list[Citation]` 证据面板数据
- `refused: bool` 是否拒答
- `rewritten_query: str` 改写后查询
- `track: str` `clinical` / `nutrition`
- `citation_check: dict` 校验明细（含 `ok` / `fake_pmids` 等）

**`citation_check` 扩展字段（B 组）**

- `retrieval_explanation: dict` 检索可解释说明（why_selected/sources/notes）
- `clinical_outline: dict` 临床赛道结构化大纲（conclusion/evidence_levels/key_studies/limitations）
- `nutrition_outline: dict` 营养赛道科普大纲（conclusion/evidence_sentence/action_tips/when_to_see_doctor）
- `refusal_reason: str` 拒答原因标识（out_of_scope / off_domain / low_relevance / empty_context）
- `suggestions: list[str]` 拒答时给出的改进问法建议

### 检索返回的单条 `dict` 常用键

- `chunk_id`, `doc_id`, `title`, `text`, `source`, `year`, `url`, `tags`, `evidence_level`, `score`
