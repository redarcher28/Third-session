# 证据智能助手 MVP · 任务分工（两组）

> 仓库：`evidence-assistant-mvp`  
> 分组原则：按架构上下游合并，减少接口扯皮；两组通过 `EvidenceDoc` / `ask()` / 建库脚本对齐。

---

## 分组总览

| 组别 | 名称 | 人数建议 | 核心职责 |
|------|------|----------|----------|
| **A 组** | 数据与知识库 | 1～2 人 | 采集 → 规范化 → 切分 → Wiki → 向量入库 |
| **B 组** | 推理·赛道·演示 | 2～3 人 | 检索 RAG → 临床/营养助手 → 评测 → 界面/API |

**依赖关系：** A 组先交付可建库 → B 组联调问答与评测。

**联调顺序：**
1. A：`python scripts/build_kb.py --skip-live`
2. B：`python scripts/smoke_demo.py`
3. B：`streamlit run src/app/ui.py`
4. B：`python scripts/run_eval.py`

---

## A 组：数据与知识库组

### 1. 职责范围

- 从 PubMed、ClinicalTrials.gov、Europe PMC、本地种子/PDF/Markdown 采集证据
- 统一为 `EvidenceDoc` 结构，合并、去重、质量报告
- 文档切分、LLM Wiki 主题页、Chroma 向量入库
- 提供稳定建库命令与知识库规模说明（供演示报告使用）

|-----------|------|

| `src/ingest/clinicaltrials.py` | 临床试验采集 |
| `src/ingest/europepmc.py` | Europe PMC 采集 |

### 4. 交付标准（验收）

- [ ] `python scripts/build_kb.py --skip-live` 无报错
- [ ] `data/processed/documents.json` 存在且条数 ≥ 本地种子规模
- [ ] `data/processed/wiki/` 下有主题页 Markdown
- [ ] 向量库 `EvidenceStore.count() > 0`（B 组 smoke 可验证）
- [ ] （可选）有采集/建库简要说明，可写入项目报告「数据来源」章节
